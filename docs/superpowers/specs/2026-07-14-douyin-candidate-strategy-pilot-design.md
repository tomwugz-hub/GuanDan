# 抖音单案例候选策略自动提炼设计

## 目标

以账号 `74480108075` 的公开视频 `7660454136994975018` 为首个试点，把已经进入 `doctrine-candidates.jsonl` 的七条待审核知识，结合用户确认的术语纠错，自动提炼为可验证但不直接生效的候选策略规则。

本试点用于验证“知识证据 → 纠错解释 → 实战启发式 → 测试场景草案”的闭环，不修改 `strategy/`，不把单一创作者观点当成已经成立的正式教义。

## 输入与证据保真

输入包括：

- 原始规范 transcript；
- `knowledge.jsonl` 与 `doctrine-candidates.jsonl` 中该视频的 pending 候选；
- 视频 ID、规范公开 URL、证据起止时间、模型与语言元数据；
- 用户确认的术语纠错记录。

原始 transcript 和原始 evidence 文本保持不可变。纠错内容单独写入 review 文件，必须同时记录原文、纠正文、时间范围、纠正来源和确认时间；候选策略引用两层文本，不能用纠正文覆盖原始证据。

本案例已确认的纠错为：

1. `下甲起手出三个9代对杀` → `下家起手出三个9带对3`；
2. `下甲出小的3代 / 大的3代 / 轮趾交换` → `下家出小的三带 / 大的三带 / 轮次交换`；
3. `对甲手发 / 顺子曲线内 / 单排` → `对家首发 / 顺子区间内 / 单牌`；
4. `10勾圈的木板` → `10、J、Q的木板`，其中木板指三连对；
5. `对甲手发四射统设杂顺` → `对家首发4张同色杂顺`。

## 提炼方案

采用“证据约束的启发式提炼”，不采用纯摘要，也不直接生成正式策略代码。

每条候选策略必须包含：

- 稳定 ID 和来源视频；
- `status: "needs-validation"`；
- 触发条件；
- 观察到的牌型或行为；
- 推断；
- 建议动作；
- 适用阶段和角色关系；
- 例外、反例与过度推断风险；
- 可信度及其理由；
- 原始证据和纠正解释；
- 可执行测试场景草案；
- `sourceCount: 1`，不得虚增来源数。

介绍性口号不生成策略。相互依赖的“观察 + 后续动作”可以合并，但不得把不同时间段、不同牌型的推断拼成一条泛化规则。

## 试点预期候选

自动运行应尝试生成以下五类启发式；实际输出可因验证规则而降级为“仅记录、暂不形成策略”：

1. 下家首手以较大三张带较小对子时，可把三张与对子之间的点数间隔作为其可能持有中间杂顺的弱信号。
2. 下家首发小三带且没有更大三带回收时，可把“保留大顺子或进行轮次交换”列为待验证假设。
3. 对家首发小顺子时，可推断其仍可能持有顺子区间内的单牌或对子；送牌时优先考虑区间外更小的牌，但必须结合已出牌和对家剩余张数。
4. 对家打出 `10-J-Q` 木板时，可把“缺少大顺子”作为弱推断，不能视为确定信息。
5. 对家首发4张同色杂顺时，可把“没有红心配”作为待验证推断。

## 自动校验与风险控制

提炼器必须自动拒绝或降级：

- 没有有效时间范围或规范来源 URL 的候选；
- 只有口号、结论但没有可观察触发条件的内容；
- 把“可能、大概率”改写为确定事实的内容；
- 无例外、无反例风险或无测试草案的策略；
- 试图写入 `strategy/`、修改正式教义或把状态设为 accepted/reviewed 的输出。

单一视频最多只能达到中等候选可信度。由于本案例存在 ASR 纠错且来源数为一，默认可信度应为低或中低；后续需要独立来源、真实牌局或模拟场景支持才能晋升。

## 输出与接口

新增一次性可重复运行的 CLI：

```powershell
npm.cmd run data:douyin:refine -- --account 74480108075 --video 7660454136994975018
```

耐久输出：

```text
training-samples/sources/douyin/74480108075/reviews/7660454136994975018.corrections.json
training-samples/sources/douyin/74480108075/strategy-candidates/7660454136994975018.json
training-samples/sources/douyin/74480108075/strategy-candidates/7660454136994975018.md
```

重复运行必须幂等：同样输入产生相同候选 ID 和语义内容；只允许生成时间等审计字段变化。不得改写 transcript、knowledge、doctrine candidates 或 manifest 状态。

## 测试与验收

实现采用测试驱动，至少覆盖：

- 原始证据与纠正文双层保留；
- 五类预期启发式的触发条件、推断和风险字段；
- 口号过滤、确定性夸大拦截、单来源可信度上限；
- 无效来源、无时间范围和未确认纠错拒绝；
- 重复运行幂等；
- 不修改 transcript、knowledge、manifest 与 `strategy/`；
- CLI 只处理指定账号和视频，拒绝路径穿越。

验收顺序：focused 测试、完整 `test:douyin`、真实试点运行、输出审计。只有未来要晋升正式策略时才生成针对正式引擎的 golden 场景并运行完整 `npm.cmd run test:gate`；本试点本身不执行晋升。
