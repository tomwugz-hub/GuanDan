# 抖音掼蛋视频本地知识采集设计

日期：2026-07-14
目标账号：掼蛋教父（抖音号 `74480108075`）

## 1. 目标与边界

为掼蛋教练 Pro 增加一条可恢复、可追溯的本地知识采集流水线，将目标账号的公开技巧视频转化为逐字稿、技巧摘要和候选教义，为后续策略审计与迭代提供材料。

本功能只处理当前登录用户能够正常访问的公开视频，不绕过登录、验证码、反爬、付费、地域或数字版权限制。原始视频和提取音频只作为临时文件，成功转写后自动删除，不提交到 Git。

主页标称作品数为 325，2026-07-14 在网页端实际观察到 306 个视频链接。清单同时记录标称数量、观察数量和不可访问差额；不可访问作品标记为受限，不通过其他规避方式补抓。

## 2. 方案选择

采用可恢复的增量流水线，不采用一次性不可恢复的批处理，也不要求人工逐条导入。

选择理由：

- 306 条视频处理时间长，登录状态、网络和本地转写都可能中断。
- 同一账号会继续发布视频，需要支持增量发现和去重。
- 每条视频必须保留来源、处理状态和失败原因，才能审计知识质量。
- 先跑单条样本，再小批量扩容，可以尽早发现媒体下载和转写环境问题。

## 3. 目录与数据模型

长期数据放在：

```text
training-samples/sources/douyin/74480108075/
  source.json
  manifest.json
  transcripts/
    <video-id>.json
  knowledge.jsonl
  doctrine-candidates.jsonl
  failures.jsonl
  reports/
    latest.json
    latest.md
```

临时数据放在 Git 忽略目录：

```text
.cache/douyin/74480108075/<video-id>/
  source.mp4
  audio.wav
```

`manifest.json` 的每条视频至少包含：

- `videoId`、`url`、标题、发布时间及账号标识；
- `discoveredAt`、`updatedAt`；
- `status` 和最近成功阶段；
- 转写、知识条目和失败记录的相对路径；
- 重试次数、最后错误类别和错误摘要；
- 内容哈希或等价去重标识。

状态集合固定为：

- `discovered`：已发现公开视频；
- `downloaded`：临时媒体已下载；
- `transcribed`：逐字稿已生成；
- `extracted`：候选知识已提取；
- `reviewed`：候选知识已完成人工或规则审核；
- `blocked`：平台限制、作品不可访问或确定不可重试；
- `failed`：可重试的下载、音频或转写失败。

## 4. 组件划分

### 4.1 清单采集器

输入账号配置和已确认的主页 URL，输出规范化清单。采集器合并已有清单，按 `videoId` 去重，保留首次发现时间，不因单次页面缺失直接删除历史条目。

采集器只消费公开页面中可见的作品链接。需要现有登录状态时，由 Codex 的浏览器辅助步骤读取可见页面并导出清单文件；仓库内的普通 Node 脚本只导入该清单，不直接控制浏览器，也不读取或导出 Cookie、密码和浏览器配置。

### 4.2 临时媒体获取器

由浏览器辅助步骤逐条确认页面当前可播放的公开媒体，并将媒体交给仓库内处理器写入 `.cache/douyin/`。媒体 URL 视为短期有效信息，不写入长期清单。下载过程限制并发、设置超时和有限重试，避免对平台造成突发请求。仓库脚本也支持导入用户合法取得的本地视频文件，以便在浏览器下载不可用时继续处理。

每条视频只有在文件完整性检查通过后才能进入 `downloaded`。平台校验、验证码、权限或作品下架直接进入 `blocked`，不实施规避。

### 4.3 本地音频与转写器

使用 FFmpeg 将视频转换为适合语音识别的单声道音频，再使用 `faster-whisper` 进行中文本地转写。转写结果包含：

- 视频标识、模型名称和模型版本；
- 语言、总时长和生成时间；
- 带起止时间的文本分段；
- 模型返回的置信度或等价质量指标；
- 原始标题和来源 URL。

模型和依赖首次安装后保存在本机环境或忽略目录，不提交大体积模型文件。首个样本默认使用 `faster-whisper` 的 `small` 模型、中文语言提示和 `int8` 计算；运行时若明确验证 CUDA 可用则允许自动选择 GPU，否则使用 CPU。模型名、设备和计算精度都可通过参数覆盖。通过单条样本测量速度和人工抽查准确性后，再决定是否扩大批次或升级模型。

### 4.4 知识提取器

知识提取器读取逐字稿，先通过确定性规则完成分段、主题初筛、重复检测和证据定位，再由 Codex 对候选片段做语义归纳与审查；它不会依赖未配置的云端模型，也不会把整段文字直接加入策略。每条知识至少包含：

- `claim`：明确、可检查的技巧主张；
- `topic`：组牌、记牌、配合、炸弹、进还贡、残局等；
- `conditions`：适用局面和前提；
- `action`：建议动作；
- `exceptions`：不适用条件或风险；
- `evidence`：视频 ID、URL、时间段和对应转写片段；
- `confidence`：转写质量、表达明确度和交叉来源支持度；
- `reviewStatus`：待审、接受、驳回或需要实战验证。

营销、商品、泛泛口号、重复内容和无法转成可验证条件的陈述不进入候选教义。

### 4.5 教义晋升适配器

候选知识不能自动修改 `strategy/`。进入策略引擎前必须：

1. 与现有 `guandan-book`、`guandan-100cases` 和策略原则对照；
2. 标记一致、补充、冲突或证据不足；
3. 为可编码主张建立 doctrine ticket；
4. 增加专项或 golden 回归场景；
5. 通过项目发布门禁后才允许修改策略实现。

## 5. 数据流与运行方式

流水线顺序为：

```text
发现作品 -> 合并清单 -> 下载临时视频 -> 提取音频
         -> 本地转写 -> 清洗分段 -> 提取候选知识
         -> 生成审计报告 -> 删除成功条目的临时媒体
```

仓库内命令行入口采用可组合模式，登录态页面读取和媒体取得由 Codex 在命令外编排：

```text
npm run data:douyin:manifest -- --account 74480108075 --input <observed-manifest.json>
npm run data:douyin:run -- --account 74480108075 --limit 1
npm run data:douyin:run -- --account 74480108075 --limit 10 --resume
npm run data:douyin:report -- --account 74480108075
```

首次验收只运行一条约 40 秒的最新技巧视频。成功后扩到小批次，再逐步处理全部可访问作品。默认串行或低并发运行，避免登录失效、磁盘突增和模型资源争抢。

## 6. 恢复、重试与清理

- 每完成一个阶段就原子更新对应状态，进程中断后从最近成功阶段恢复。
- 下载和临时网络错误进行有限次数退避重试；确定的权限、验证码或下架问题不自动重试。
- 转写失败保留完整视频，便于重试；转写成功后删除视频，仅在知识提取仍需音频时暂时保留音频。
- 知识提取成功或明确失败后清理音频。
- 运行前后记录临时目录大小，报告未清理文件。
- 同一视频重复出现时复用已有逐字稿，除非明确指定重新转写或模型版本发生迁移。

## 7. 安全与合规

- 不在日志、清单或代码中保存 Cookie、签名媒体 URL、访问令牌或浏览器配置。
- 不自动点赞、关注、评论、私信或投稿。
- 不绕过平台访问保护，不自动处理验证码。
- 只保存用于项目研究的转写、短证据片段和结构化分析；原媒体不长期归档。
- 大模型或云端转写不在本设计范围内；若未来需要上传媒体，必须单独确认数据目的地和费用。

## 8. 测试与验收

自动测试至少覆盖：

- 清单解析、规范化、去重和历史条目保留；
- 合法状态迁移和断点续跑；
- 下载失败、不可访问、转写失败和有限重试；
- 成功与失败路径的临时文件保留/清理规则；
- 逐字稿数据结构、时间段排序和来源追踪；
- 知识条目字段校验、低质量过滤和证据引用；
- 报告中的标称数量、观察数量、成功数、受限数和失败数一致性。

端到端验收标准：

1. 目标账号身份、325 条标称作品和 306 条已观察链接被正确记录；
2. 一条公开样本完成下载、音频提取、本地转写和知识提取；
3. 逐字稿含时间戳与来源，候选知识能够回到原视频时间段；
4. 成功后原视频和音频被删除；
5. 第二次运行不会重复处理成功条目；
6. 受限作品被记录但不触发规避行为；
7. 新增测试以及现有 `npm.cmd run test:gate` 通过。

## 9. 非目标

- 不永久训练或修改语言模型参数；
- 不保证获得主页标称但网页端不可见的 19 条作品；
- 不将单个博主的观点直接视为正确规则；
- 不在本阶段建立可视化后台、定时云任务或高并发抓取集群；
- 不自动提交候选教义到生产策略。
